# Edits — active work claims (read this before you touch any file)

Purpose: multiple AI tools (Antigravity, Codex, opencode, Kilo Code, Claude Code, ...) may be working in this repository at the same time, possibly in parallel sessions. This file is how they avoid editing the same files at the same time and stepping on each other's work. It is **not** optional — check it before every editing session, and keep it updated while you work.

## The protocol

1. **Before you start editing:** read the "Active claims" table below. If any row overlaps the files/directories you're about to touch and its `Status` is `in-progress`, **do not start**. Either wait, pick different work, or (if truly necessary) ask the human to resolve the conflict. Don't silently edit the same files as an active claim.
2. **Claim your work:** add a row to "Active claims" *before* you start editing: your tool name, the branch, the files/paths (be specific — a package name or a short list of files, not "everything"), and a one-line description of the task. Timestamp in UTC, ISO-ish (`YYYY-MM-DD HH:MM`).
3. **While working:** if your scope grows to touch files outside your claim, update your row rather than silently expanding scope.
4. **When done:** move your row from "Active claims" to "Completed log" (append it at the bottom, newest last), changing `Status` to `done`. If you abandoned the work, mark it `abandoned` with a short reason instead of deleting the row.
5. **Editing this file itself:** only append or edit your own row. Don't rewrite or reformat other agents' rows or reorder the tables — that causes the exact collisions this file exists to prevent. If the file gets messy, ask the human before doing a cleanup pass.
6. **Stale claims:** if a claim's timestamp is more than ~4 hours old and looks abandoned (no corresponding recent commits on that branch touching those paths), you may treat it as stale — but say so explicitly in your own commit/summary rather than deleting it silently.
